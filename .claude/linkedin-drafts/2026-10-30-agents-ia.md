## Post (FR)

🤖 Un agent IA qui code, c'est rapide. Cinq agents cadrés et un humain qui tranche, c'est une méthode.

Le cas concret : un petit outil PowerShell de maintenance Windows pour un proche.

Mon organisation :
- un agent principal qui code et orchestre ;
- 4 sous-agents spécialisés, chacun avec un rôle, des outils limités et des garde-fous écrits : documentation et spécifications, recommandations Microsoft Learn, commits git… et LinkedIn (il a rédigé ce brouillon, je l'ai relu) ;
- moi : les décisions produit et les tests, sur une VM Windows 10 neuve, sur le poste d'un proche, puis sur Windows 11.

🔍 Ce que ça a changé
- winget absent sur Windows 10 neuf : l'expert Microsoft a trouvé la méthode officielle et annoncé le risque 0xC0000135 sous SYSTEM. Il est survenu au test suivant.
- Le rédacteur a repéré des écarts entre code et spécification avant les tests.
- Le gestionnaire git s'est arrêté au lieu d'inventer une identité absente. J'ai tranché.
- 38 exigences EARS, critères Gherkin et traçabilité, mises à jour à chaque retour de test.

💡 Ce que j'en retiens
L'IA accélère, mais la valeur vient du cadrage : des rôles, des limites, des garde-fous. Et d'une boucle pilotée par un humain : test terrain → diagnostic → spec → code.

Et vous, quels garde-fous donnez-vous à vos agents IA ?
